# 01 · 架构设计

## 目标

让 LVGL 代码在项目变多后依然不乱：一个仓库承载多个 UI 应用、多个目标平台、不同 LVGL 版本，
且 UI 与业务逻辑彻底解耦，PC 上模拟、板子上移植，代码复用最大化。

## 设计原则

1. **单一仓库、多应用、多平台**（monorepo）：应用与平台正交，`APP × PORT` 组合构建。
2. **三层解耦**：View（UI）— Presenter（胶水）— Model/Service（业务）。
3. **平台抽象**：所有平台实现同一个 `port.h`，应用对平台零感知。
4. **LVGL 版本隔离**：版本相关代码只出现在 `ports/*` 与 `apps/*/ui`。
5. **一套代码、两种构建**：PC/Linux 走 CMake；MCU 走 CMake 或厂商 IDE 拷贝清单。

## 目录结构与职责

```
apps/<app>/                 UI 应用（自包含：lv_conf.h + main.c + 四层源码）
ports/<port>/               平台实现（实现 shared/port/port.h）
shared/                     跨应用复用（无硬件依赖）
  port/port.h               ★ 唯一硬件契约
  app/                      应用生命周期 + 统一主循环
  ui/widgets, ui/themes     可复用控件 / 主题
  utils/                    日志等（零 LVGL 依赖）
lvgl/                       LVGL 库（vendor，pin 版本）
cmake/                      lvgl_helpers.cmake + toolchains/
docs/                       文档
```

## 分层规则（铁律）

| 层 | 目录 | 允许 | 禁止 |
|----|------|------|------|
| View | `apps/*/src/ui/` | 操作 LVGL 控件、回调 Presenter | 写业务规则、直接访问硬件 |
| Presenter | `apps/*/src/presenter/` | 翻译 UI 事件 ↔ Model/Service | 持有大量布局代码 |
| Model/Service | `apps/*/src/model/`、`src/service/` | 纯 C 业务逻辑、可单测 | **`#include "lvgl.h"`**、触碰 LVGL 类型 |
| Port | `ports/*/` | 显示/输入/tick、主循环协作 | 包含任何业务逻辑 |
| Shared | `shared/` | 通用组件/框架/工具 | 依赖具体 app 或具体板子 |

**验收方式**：`grep -R "lvgl.h" apps/*/src/model apps/*/src/service` 应为空。

## 关键接口契约

```c
// shared/port/port.h —— 每个平台必须实现（ports/<name>/src/port.c）
typedef struct {
    void     (*init)(void);           // 创建并注册 display + 输入设备 + tick
    uint32_t (*tick_ms)(void);        // 单调毫秒
    void     (*delay_ms)(uint32_t ms);// 主循环节奏（MCU/RTOS 上=任务让出）
} port_api_t;
const port_api_t *port_get(void);

// shared/app/app.h —— 每个应用必须实现
void app_init(void);                  // 构建 View + 组装 Presenter
void app_update(void);                // 可选：周期业务任务（弱符号，默认空）
void app_run(void);                   // 统一主循环

// apps/*/src/main.c —— 所有应用共用同一极薄骨架
int main(void) {
    lv_init();
    port_get()->init();
    app_init();
    app_run();
    return 0;
}
```

## 四项核心需求如何落地

### 1. MCU 与 Linux 板卡移植
统一契约 `port.h` 是唯一差异点。Linux 板走 CMake + toolchain；MCU 走 CMake 或厂商 IDE 拷贝清单。
移植只改 `ports/*`，`apps/*`、`shared/*` 零改动。

### 2. LVGL 版本
LVGL vendor 在 `lvgl/` 并 pin 版本。版本相关 API 差异只出现在 `ports/*`（驱动）与 `apps/*/ui`（控件）；
`model/service/shared/utils` 零依赖，天然免疫。升级路径见 `docs/05`。

### 3. 多个 UI 应用
每个应用 = `apps/<name>/` 自包含（自己的 `lv_conf.h`）。一次只构建一个 `-DAPP=<name>`，
不同应用可有不同 LVGL 特性/内存配置，互不干扰。新建应用 = 复制 `hello_world` 模板。

### 4. 架构可复用
`shared/ui`、`shared/utils`、`shared/app` 跨应用复用；`cmake/toolchains`、`ports/*` 跨项目复用；
`tools/` 集中资源转换，避免散落。

## 构建编排

顶层 `CMakeLists.txt`：
1. 读 `-DAPP=` / `-DPORT=`（默认 `demo_widgets` / `pc_sdl`）。
2. 把 `apps/<APP>/lv_conf.h` 设为 `LV_BUILD_CONF_PATH`（应用专属配置）。
3. `add_subdirectory(lvgl)` → `shared` → `ports/<PORT>` → `apps/<APP>`。
4. `cmake/lvgl_helpers.cmake` 的 `lvgl_add_app()` 统一创建应用目标、链接依赖、设输出目录。

## 边界与约定

- **一次 configure 只选一个 APP**（不同 app 的 lv_conf.h 互斥）。
- **所有 include 用相对路径**，保证 MCU IDE 拷贝清单可用。
- **PC 入口用普通 `main()`**，不依赖 SDL2main（见 ports/pc_sdl/CMakeLists.txt 注释）。

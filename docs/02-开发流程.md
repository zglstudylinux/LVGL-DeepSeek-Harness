# 02 · 开发流程

「模拟先行，移植在后」的标准工作流，以及新建应用 / 新增平台的标准步骤。

## 标准工作流（每个 UI 从 0 到提交）

> 真实业务示例参考 `apps/bt_speaker/`：竖屏 480×640 蓝牙音箱「正在播放」界面，
> 完整演示了 model（`model_player`/`model_playlist`）→ presenter（`presenter_player`）→
> view（`view_player`）三层解耦，UI 层才 include `lvgl.h`。

1. **复制模板**：`apps/hello_world` → `apps/<新应用名>`。
2. **写代码**（按分层）：
   - `src/ui/` 画界面；
   - `src/presenter/` 写胶水；
   - `src/model/`、`src/service/` 写业务（**不要 include lvgl.h**）。
3. **PC 跑通**：`.\build.ps1 -App <新应用名> -Run`。
4. **提交**：`git add apps/<新应用名> && git commit -m "add app <新应用名>"`。
5. **需要上板**：新增/选择 `ports/<板卡>`，同一应用直接构建，app 代码零改动。

## 新建一个应用（复制模板）

```powershell
Copy-Item -Recurse apps/hello_world apps/my_app
```

改 `apps/my_app/CMakeLists.txt`：把 `lvgl_add_app(hello_world ...)` 改成 `lvgl_add_app(my_app ...)`，
并列出你的源文件。构建：

```powershell
.\build.ps1 -App my_app -Run
```

**写文档**：按 [docs/06-应用文档规范.md](06-应用文档规范.md) 的模板写 `apps/my_app/README.md`
（含 Mermaid 总体架构图、数据流时序图、业务流程图、接口契约、扩展指南），与代码同一次提交。

`lv_conf.h` 是应用专属的：可在 `apps/my_app/lv_conf.h` 按需裁剪特性（如关掉 demos、调大/调小内存池）。

## 新增一个目标平台

### CMake 型（PC / Linux）
1. 复制 `ports/pc_sdl`（或 `ports/linux_fb`）→ `ports/<新平台>`。
2. 实现 `src/port.c` 的 `port_get()` 三函数（显示/输入/tick/delay）。
3. 若需交叉编译，写 `cmake/toolchains/<平台>.cmake`。
4. 构建：`cmake -B build -DPORT=<新平台> -DAPP=my_app -DCMAKE_TOOLCHAIN_FILE=...`。

### MCU 型（厂商 IDE）
按 `ports/stm32f4xx/README.md` 的拷贝清单，把 `lvgl/ + shared/ + ports/<芯片>/ + apps/<应用>/` 加入工程。

## 常用命令速查

| 操作 | 命令 |
|------|------|
| 构建 demo | `.\build.ps1 -App demo_widgets` |
| 构建并运行 | `.\build.ps1 -App hello_world -Run` |
| 全清重建 | `.\build.ps1 -App demo_widgets -Clean` |
| 校验业务层零 LVGL 依赖 | `grep -R "lvgl.h" apps/*/src/model apps/*/src/service` |

## 提交纪律

- 每个应用/平台改动**独立提交**，提交信息写明 `apps/<name>` 或 `ports/<name>`。
- 新建应用必须同时提交 `apps/<app>/README.md`（按 `docs/06-应用文档规范.md` 模板）。
- 不要提交 `build/`、`bin/`（已在 `.gitignore`）。
- 图片/字体转换产物放到对应应用的 `src/ui/` 或 `shared/ui/`，不要散落根目录。
